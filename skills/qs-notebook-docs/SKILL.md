# QS 项目 Notebook 文档撰写与维护

将 Notebook 作为同一份文档源，服务直接使用、Markdown 阅读和 Skill 检索。正文、代码示例和标签共同维护；保留用户指定的范围、格式与已有改动。

## 开始前确认依据

- 根据用户指定的文件或任务确定目标项目、仓库根目录和文档位置；Skill 的存放仓库不决定目标项目。支持在 QuantStudio、QSExt、QSResearch 等项目中使用。
- 阅读目标项目中适用的 `AGENTS.md`、`CLAUDE.md`、文档通则和相邻文档（以实际存在的文件为准），确认源码与文档目录、Python 环境和维护规范。
- 查找目标项目已有的转换器、文档构建入口、Skill 生成入口、导航及参考文档索引。路径、命令、输出目录和解释器均以目标项目为准，不从 Skill 所在仓库套用。
- 修改前检查工作区差异和目标单元，保留用户已有内容、其他标签、单元 ID、附件及无关输出。使用 UTF-8，沿用原文件的 JSON 缩进，避免整篇无关重排。
- 文档以中文编写，代码注释用中文，Python 文档字符串使用 Google 风格。
- 说明 API 时核对当前源码、参数模型和调用位置。现有文档用于了解结构，不以旧示例或对话中的结论替代源码核对。

## 从使用者需要组织内容

优先回答适用场景、如何配置、如何调用、得到什么结果、如何处理常见问题。用最小真实示例引入概念，避免以类继承树、内部字段、调度队列或大段帮助输出作为使用说明的主体。

- 使用篇只概括理解接口所必需的原理，并链接到详细说明。
- 共同的底层机制集中维护，遵循目标项目已有组织和用户指定的目的地。例如可以集中到“原理和细节.ipynb”，使用篇保留概括与链接；不固定放到某个项目或模块。
- 涉及 `QSID`、`InstanceID`、`RunID`、`DataVersion` 等概念时，说明它们对调用、状态隔离或缓存复用的实际影响。实现细节按需链接，不在多篇使用文档中重复展开。
- 移动内容时同步调整原位置的概括、相关链接和目录，保留仍有参考价值的说明，并修正与当前源码不符的描述。

共用正文使用与展示媒介无关的表述。删除“建议从上到下执行本篇”“先运行另一个 Notebook”“执行上一个单元后再继续”等操作指令；保留 `engine.run()` 等业务 API 的运行语义。“下面的示例”“相关说明见……”可用于连接上下文。

若确实需要仅面向 Notebook 的操作说明，将其放在独立单元并设置相应排除标签。公共正文中的文档链接使用相对 `.ipynb` 路径，并检查目标项目的转换器是否正确生成对应的 `.md` 链接。

## 管理三种用途的收录范围

默认保留单元，通过以下标签排除；不再使用旧的 `skill` 标签。

| 单元标签 | Notebook 直接使用 | Markdown 文档 | Skill 参考资料 |
|---|---|---|---|
| 无排除标签 | 保留 | 保留 | 保留 |
| `md-excluded` | 保留 | 排除 | 保留 |
| `skill-excluded` | 保留 | 保留 | 排除 |
| 两个标签同时设置 | 保留 | 排除 | 排除 |

两个标签独立生效：生成 Skill 时只应用 `skill-excluded`，不叠加 `md-excluded`。规则适用于代码、Markdown、raw 等所有单元类型；排除整个单元及其输出，不改变 Notebook 直接使用的行为。

核对目标项目的生成器是否已支持这些规则；若不一致，按本次任务范围处理并说明差异，不仅凭写入标签就认定导出已经生效。

```json
{"metadata": {"tags": ["md-excluded", "skill-excluded"]}}
```

按内容用途判断，不把所有 import 或所有图表一律排除：

- 真实 API 示例、必要的导入与配置、便于理解的返回结果，默认保留。
- 仅供 Notebook 使用的日志设置、警告过滤、显示环境配置和交互渲染，通常同时标记两个排除标签。
- 仅打印方法签名、正文已有说明的帮助单元，可在 Markdown 中保留，并标记 `skill-excluded`。
- 本机路径、环境专属初始化、巨大的低信息量报告等，按目标用途排除。计算代码与交互显示混在同一单元时，先拆开，再分别设置标签。
- 删除旧 `skill` 标签时复核原有收录意图；原来未被收录的代码可能需要改为 `skill-excluded`。保留 `demo_data` 等无关标签。

正文不应引用被该目标格式排除的单元作为必要解释，也不要在删除展示单元后留下“如下图”之类的悬空引用。

## 编写代码示例与图形展示

- 示例应符合当前真实 API，优先使用确定性的本地小数据。每篇 Notebook 的变量和依赖在本篇定义，不依赖另一个 Notebook 的内核状态。
- 配置放在公开参数或依赖模型中；自定义 Node 的业务参数按当前框架约定声明，避免只存入构造器私有属性而破坏克隆、模板或身份语义。
- 让导出后的示例保留必要的调用上下文，展示有意义的结果。清除修改后失效的旧输出；仅重新执行受影响的示例及其必要前置单元。
- 不将本机解释器、用户目录、凭据或特定数据库环境固化到共享文档与 Skill。遵循当前项目环境约定；外部数据配置由调用方提供或查询获得。
- 新增辅助脚本和测试遵循目标项目的目录约定；功能脚本开头用中文模块文档字符串说明实现逻辑和使用方法。普通 Notebook 编辑无需额外创建脚本。

包的安装由使用者处理，不添加 `find_spec` 检查、捕获缺包异常或提示改用其他查看器的降级分支。

将图文本生成与 Notebook 渲染拆开，图文本生成调用以目标项目实际使用的 API 为准。若使用 QuantStudio 计算图节点，可使用其依赖提供的可视化工具；以下生成单元默认保留，其中 `node_list` 应由本篇前文定义：

```python
from QuantStudio.Tools.Visualization import node2dict, dict2mermaid

graph_text = dict2mermaid(node2dict(node_list), direction="TD")
```

以下显示单元设置 `md-excluded` 和 `skill-excluded`，供直接使用 Notebook 时显示：

```python
from IPython.display import display
from mermaid import Mermaid

display(Mermaid(graph_text))
```

生成 Markdown 需要展示图形时，使用适合该格式的 Mermaid 代码块，或保留现有适配方式；不要依赖被排除的 Notebook HTML 输出。

## 验证与更新派生产物

以改动范围选择验证，使用当前项目指定的 Python 虚拟环境：

- 文字、链接或标签修改：校验 Notebook 结构、检查差异和链接，并检查相应导出内容；无需为了文字调整执行外部数据计算。
- 代码示例修改：在干净环境中验证受影响示例与必要前置依赖。需要验证整篇独立性时使用新内核，避免已有变量掩盖问题。缺少数据库、数据或依赖时，说明未验证部分和原因。
- 转换逻辑修改：运行目标项目已有的导出回归测试，按项目要求补充受影响检查；验证默认保留、标签独立、整单元与输出排除，以及不修改源 Notebook。

确认目标项目中哪些文件是 Notebook 源文件、哪些是生成的 Markdown、站点或 Skill 参考资料。维护源文件，由该项目的生成入口更新派生产物，不直接修改生成文件。

修改 Notebook 后，按目标项目已有流程重新生成相关 Skill 参考资料；需要更新或验证 Markdown 文档与站点时，调用该项目相应的构建入口。命令应在目标项目要求的工作目录下执行，使用其指定的 Python 环境。

新增、改名或移动文档时，检查目标项目实际使用的导航配置、跨篇链接和 Skill 参考文档索引。不假设它一定使用 MkDocs 或某个固定名称的 Skill。

检查实际产物：排除的初始化或渲染单元及其输出应消失，公共示例仍保留，标题与链接有效。核对并复用目标项目已有的图片剥离、环境输出清理、执行计数处理等功能，避免重复实现转换逻辑。

若目标项目尚无相应构建流程，完成源文档编辑与可行验证，并说明未生成的产物；是否新增转换器按用户任务范围决定，不自动移植另一个项目的整套构建配置。

交付时简要说明修改了哪些文档、关键组织变化和验证结果。区分通过、未运行和未完成的检查；构建中的已有问题单独说明，不扩大本次修改范围。
