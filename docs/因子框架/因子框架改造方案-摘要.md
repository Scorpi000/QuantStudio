# 因子框架改造方案 - 摘要

## 问题

当前因子框架将截面ID（SectionIDs）和时点标尺（DTRuler）作为因子的固有属性，导致：

1. **同一因子无法被不同截面调用** - 初始化时强制检查一致性
2. **缓存无法隔离** - 缓存键只用QSID，不含维度信息
3. **初始化逻辑复杂** - init_compute 职责过多（100+行）

## 核心思想

**分离"计算维度"和"返回维度"：**

```
计算维度 = 因子计算需要知道的完整范围（截面 + 时点）
返回维度 = 用户请求返回的范围（可能更小）
缓存     = 按（因子 + 计算维度）存储
```

## 设计要点

### 1. 缓存键生成

```python
def make_cache_key(qsid, section_ids=None, dtruler=None):
    """生成缓存键 = 因子QSID + 截面哈希 + 时点哈希"""
    parts = [qsid]
    if section_ids:
        parts.append(f"s:{','.join(sorted(section_ids))}")
    if dtruler:
        parts.append(f"d:{','.join(str(d) for d in dtruler)}")
    return hashlib.md5("|".join(parts).encode()).hexdigest()[:16]
```

### 2. Factor.readData 签名变更

```python
# 旧签名
def readData(self, ids: List[str], dts: List[dt.datetime]) -> pd.DataFrame

# 新签名
def readData(
    self, 
    ids: List[str],              # 返回的证券
    dts: List[dt.datetime],      # 返回的时点
    section_ids: Optional[List[str]] = None,  # 计算截面（可选）
    dt_ruler: Optional[List[dt.datetime]] = None  # 计算时点（可选）
) -> pd.DataFrame
```

### 3. 缓存键变更

```python
# 旧缓存键
cache_key = QSID

# 新缓存键（因子QSID + 截面哈希 + 时点哈希）
cache_key = make_cache_key(factor.QSID, section_ids, dtruler)
```

### 4. 移除的内容

- `Factor.__QS_ArgClass__.SectionIDs` - 截面不再是因子属性
- `FactorContext.SectionIDs` - 不再需要全局截面
- `init_compute` 中的截面一致性检查（330-331行）

**保留的内容（用于优化）：**
- `FactorInitData.SectionIDs` - 用于 `prepare_compute` 阶段批量准备数据

**算子维度配置：**

| 算子类型 | DescriptorSection | DescriptorDTRuler | 原因 |
|----------|-------------------|-------------------|------|
| `PointOperator` | ❌ | ❌ | 单点运算，每个点独立计算 |
| `TimeOperator` | ❌ | ✅ | 时序运算，需要回溯历史，可能涉及不同频率 |
| `SectionOperator` | ✅ | ❌ | 截面运算，需要知道完整截面 |
| `PanelOperator` | ✅ | ✅ | 面板运算，需要时序+截面 |

## 使用对比

### 旧设计

```python
# 定义时绑定截面
factor = DataFactor(data=data, args={"SectionIDs": hs300})

# 无法用不同截面调用
# factor.readData(ids=all_market, dts=dts)  # 报错！
```

### 新设计

```python
# 定义时不绑定截面
factor = DataFactor(data=data)

# 可以用任意截面调用
result1 = factor.readData(ids=hs300, dts=dts)
result2 = factor.readData(ids=all_market, dts=dts)

# 指定计算截面（全市场计算，返回沪深300）
result3 = factor.readData(
    ids=hs300, 
    dts=dts,
    section_ids=all_market
)
```

### 截面排名场景

```python
# 算子定义：在全市场截面上排名
rank_op = SectionRank(args={"DescriptorSection": [all_market]})
rank = rank_op(close)

# 场景A：全市场排名，返回300只
# 算子的 DescriptorSection = all_market（固定）
# 因子的 SectionIDs = all_market（与算子一致）
result_a = rank.readData(
    ids=hs300,
    dts=dts,
    section_ids=all_market
)
# 缓存键：rank_qsid_all_market_qsid

# 场景B：300内部排名
# 需要创建新的算子，DescriptorSection = hs300
rank_op_b = SectionRank(args={"DescriptorSection": [hs300]})
rank_b = rank_op_b(close)

result_b = rank_b.readData(
    ids=hs300,
    dts=dts,
    section_ids=hs300
)
# 缓存键：rank_b_qsid_hs300_qsid
```

### 不同频率组合

```python
# 日度因子需要月度描述子
# 比如：日度因子需要"月末市值"
monthly_market_cap = ft.getFactor("market_cap")

daily_factor = TimeOperation(
    descriptors=[monthly_market_cap],
    args={
        "Operator": makeFactorOperator(calc_func, operator_type="Time"),
        "LookBack": [1],  # 回溯1期
        "DescriptorDTRuler": [monthly_dtruler]  # 描述子是月度频率
    }
)
# LookBack=1 + DescriptorDTRuler=月度 → 回溯1个月
```

| `Node.py` | 可选简化 |

## 优势

1. **职责清晰** - 计算维度 vs 返回维度分离
2. **缓存隔离** - 不同计算维度自动隔离
3. **灵活调用** - 运行时可动态指定计算维度
4. **代码简化** - 移除 init_compute 中的复杂检查
5. **统一模型** - 截面和时点用同一套机制处理
